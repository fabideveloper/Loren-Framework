Luau framework for Roblox 2.0 beta

Write the game. Loren wires it up.

Loren is a Luau framework for Roblox. You write Services for the server and Controllers for the client. Loren starts them in the right order, hands each one what it needs, and carries calls and signals between them.

How it wires

Services on the server. Controllers on the client.

Each module lists what it needs by name. Loren loads everything, sorts it and starts it in order, then carries calls and signals between the two sides. You never write a require path to another module, and you never create a RemoteEvent.

“Frameworks should be boring. Your game shouldn’t be.”

A whole service

Here’s a Service, start to finish.

Two files. No RemoteEvents, no require paths. It’s a trimmed version of the PointsService premade (loren inject service PointsService).

Build your first service

src/server/Services/PointsService.luau

  1. 01
  2. 02
local PointsService = {
	Client = {},
	Signals = { "PointsChanged" },
}

local points: { [Player]: number } = {}

function PointsService:AddPoints(player: Player, amount: number)
	points[player] = (points[player] or 0) + amount
	self.Signals.PointsChanged:Fire(player, points[player])
end

function PointsService.Client:GetPoints(player: Player): number
	return points[player] or 0
end

return PointsService
  1. 01

    Line 3: Signals = { "PointsChanged" } is all the setup. Fire it for one player, a list, everyone, or everyone but one.

  2. 02

    Line 13: Client methods get the calling player first. Loren fills it in from the connection, so a client can’t pretend to be someone else.

src/client/Controllers/HudController.luau

  1. 03
  2. 04
  3. 05
local HudController = {
	Dependencies = { "PointsService" },
}

function HudController:LorenBurn()
	local Points = self.Dependencies.PointsService

	Points.Signals.PointsChanged:Connect(function(total)
		print("Points:", total)
	end)

	local ok, total = Points.Try:GetPoints()
	if ok then
		print("Starting with", total)
	end
end

return HudController
  1. 03

    Line 2: Dependencies = { "PointsService" } gives the Controller a proxy. Its methods return Promises.

  2. 04

    Line 5: LorenBurn is the “run” hook. It runs once every module has started.

  3. 05

    Line 12: Try waits for the answer and gives you ok plus the values. On failure you get a message and an info table instead.

What you get

  • What’s in the box.

    Eight parts, each with its own page in the docs. Pick one.

  • Core→

    Services and Controllers

    Server and client modules with the same shape. Point Loren at a folder and it starts them.

    src/
├─ server/Services/
│  └─ PointsService.luau
└─ client/Controllers/
   └─ HudController.luau

Loren.AddServices(script.Parent.Services)
  • Core→

    Dependencies by name

    List what a module needs. Loren works out the start order and catches typos, with a suggestion.

    ‘DataServce’ is not a registered Service. Did you mean ‘DataService’?

  • Network→

    Calls that return Promises

    Every call has a timeout and fails with an error code instead of hanging. Rather skip the Promise? Try gives you ok plus the values.

    10sdefault timeout, per method

  • Network→

    Signals and client events

    Server to client and client to server. Reliable or unreliable, ordered if you want.

    ↓ Signals↑ ClientEvents

  • Network→

    Typed specs

    Describe arguments and Loren checks them, then packs them smaller.

    T.u16 T.string(32) T.Vector3

  • Network→

    Middleware

    Run a check before a handler. Return true to let the call through. Anything else blocks it.

    return true → throughfalse, nil, anything else → blocked

  • Tools→

    Tests without a server

    Loren.Testing mounts a Service in a spec, fires its events and resets between tests.

    Mount Fired Emit Reset

  • Tools→

    A CLI that sets it up

    loren init makes a project for Rojo, Argon or Studio’s Script Sync. loren update upgrades it.

    $ loren init my-gameRojo · Argon · None

Get started

Four steps. The last one is Play.

It’s a beta. Try it on a side project, something you can afford to break, and tell us what broke. Paste the boot report when you open an issue.

Get started →Open an issue ↗ (opens in a new tab)

Coming from 1.5.1? Run loren update in your project. Upgrade guide →

~/my-game
  1. 01

    Install the beta

    $npm i -g loren-framework@next

    You need Node 18 or newer. The beta is on the next tag until 2.0 is stable. Plain npm i -g loren-framework still installs 1.5.1.

  2. 02

    Make a project

    $loren init my-game

    Pick Rojo, Argon or None. None uses Studio’s built-in Script Sync, so there’s nothing else to install. You get the runtime, a bootstrap script, and an example Service and Controller.

  3. 03

    Connect Studio

    $loren serve

    Then connect the Rojo or Argon plugin. With Script Sync you sync four folders once instead.

  4. 04

    Press Play

    Studio Output

    (LORENঌ) Burning on Server: 1 service, 0 routes, 4 ms

    (LORENঌ) Burning on Client: 1 controller, 0 services, 180 ms

    Loren prints one “Burning on Server” line when it’s up (burning is Loren’s word for running). If something’s wrong, you get one report that lists every problem, with a suggestion when it spots a typo.
